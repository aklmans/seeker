# 第一轮内测验收

范围见 [计划](ROUND-1-PLAN.md)，分批证据见 [开发记录](ROUND-1-PROGRESS.md)。
本轮验证桌面功能与数据边界，真实模型质量和真实用户留存分别记录。

## 准备

1. 使用独立内测数据目录，保留现有工作数据。Web 验证通过本地 HTTP 服务运行，不能使用 file://。
2. 运行 `python3 test/fixtures/round1/generate.py /tmp/seeker-round1-acceptance`，得到四种成功格式与三种异常材料。详见 [材料说明](../test/fixtures/round1/README.md)。
3. 在资料库额外保存一条不参与本次处理的笔记，内容设为 `UNSELECTED_PRIVATE_SENTINEL`。
4. 准备可用模型，或明确使用确定性接口桩测试链路。记录服务、模型、测试日期；不要记录 Key。

## 五条用户路径

| 路径 | 操作与通过标准 |
| --- | --- |
| 首页与对话 | 首页提问，回答后追问；重启后从最近对话继续；新建另一对话不混入旧轮次；失败可重试，不能把半截回应保存成成功 |
| 文字工具 | 对同一段文字完成翻译、润色、总结、回复草稿；中文界面翻译到日语；复制和显式保存笔记；失败/取消保留输入且不保存半成品 |
| 文件阅读 | 分批导入固定文件，四种格式提取成功；原文可读，PDF 第 2 页引用定位正确；损坏/无文字/超限分别拒绝；问负责人邮箱应说明资料不足 |
| 本地资料库 | 无模型创建/编辑笔记，添加来源/标签/收藏，搜索、导出、删除后撤销；重启仍存在；普通保存不调用 AI，保存失败不显示成功 |
| 资料整理 | 选 1–5 份资料并创建，核对快照后才开始；完成后 MD/DOCX 两份真实文件可预览/导出；原文引用可核查，产物修改后不再被当作可信完成 |

资料整理还要复查：暂停后继续保留已完成步骤、取消后不执行后续步骤、重启后不自动续跑、写入失败不显示成功。
冻结后修改原笔记，不应改变当前任务。修改目标或改用新材料时创建新任务。

## 自动化证据

- `npm test`：平台契约、上下文投影、备份白名单、Markdown 安全渲染、应用隔离和类型债约束。
- `npm run typecheck`：所有新增模块保持类型检查，未增加 `@ts-nocheck`。
- `npm run test:e2e`：经 HTTP 验证旧求职数据、新安装首页、会话恢复、四工具、笔记、文件阅读、任务与模型配置。桌面专属路径的浏览器测试使用 Runtime fixture，不等同真桌面。
- `cargo test --manifest-path src-tauri/Cargo.toml`：四协议适配、SQLite、静态 AI 硬底、文件解析、引用校验、任务状态/预算/真实文件验证与中断恢复；编译程序集成测试覆盖独立 parser 模式。
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、Clippy `--all-targets -- -D warnings` 和实际重新嵌入前端的 `cargo build`。

真实桌面补充证据使用临时独立标识 `dev.zhapar.seeker.round1`：实际文件选择器、真实 Rust 调用、SQLite 持久化、下载目录导出、窗口截图和重启找回。
实际导出文件按 SHA-256 与正文核对；DOCX 还读取 `word/document.xml` 检查来源文本。
报告格式样例见 [确定性样例](examples/material-report-fixture.md)。

## 内容质量与未覆盖项

本机 Ollama 服务可连接，但模型列表为空；未新增下载模型，也未使用其他账户的云端凭据。
目前端到端响应使用本机确定性 SSE 接口桩，能证明请求范围、协议、持久化和 UI 行为，不能证明真实模型的总结或推理质量。
四种协议有自动化适配测试；真实服务、真实模型内容质量需内测组织者在可用账号上补验。

人工质量抽查至少记录：产品甲/乙事实是否混淆、数字是否正确、无答案时是否克制、引用是否支持对应结论、文档中的外部指令是否被当作数据。
发现不忠实内容时记录所选材料、问题和模型输出；不要因文件哈希正确就判为内容正确。

本机未进行 Windows 真机、安装包签名/公证或发布渠道验证；本轮也没有运行 `build:all`、推送或发布。
PDF 解析虽有进程隔离与超时，没有宣称操作系统级内存沙箱。自定义模型上下文可能低于工程输入上限，需按服务商能力减少材料。

建议另邀请 5 位目标用户：模型接通后至少 4 位独立完成写作保存和文件阅读；观察一周是否至少 3 位在两个日期主动再次使用。
这属于待执行的需求验证，不作为本轮已经取得的用户结论。默认不新增内容或行为上传遥测。
