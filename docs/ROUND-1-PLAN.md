# Seeker 第一轮开发计划 · 功能内测交付

状态：五批功能和本机工程验收已完成；真实模型质量、Windows 真机与目标用户试用仍待对应环境验证。以下保留首轮范围，完成证据见 ROUND-1-PROGRESS.md，未覆盖项见 ROUND-1-ACCEPTANCE.md。尚未打包、推送或发布。

**交付目标**

交付一个面向普通办公用户的桌面功能内测版：用户能够提问、写作翻译、阅读文件、保存资料，以及让助手把几份资料整理成可检查、可导出的报告。保留 Tauri、原生前端、本地优先和现有视觉语言。

第一轮验证的问题是：用户能否独立完成这些操作，以及是否愿意再次使用。功能数量不作为主要成功指标。

**本轮必须走通的五条用户路径**

1. 打开首页 → 新建对话 → 提问并继续追问 → 关闭重开后找到对话并继续。
2. 粘贴一段文字 → 选择翻译、润色、总结或回复草稿 → 查看结果 → 复制或保存为笔记。
3. 选择文件 → 看到解析结果 → 总结或提问 → 从引用回到对应原文片段。
4. 新建笔记或收藏片段 → 编辑、搜索和筛选 → 重启后仍保留；没有模型也能使用。
5. 选择几份资料 → 填写整理目标 → 核对材料和交付内容 → 执行任务 → 预览报告、核查引用并导出。

**功能范围与完成标准**

| 模块 | 本轮交付 | 验收重点 |
| --- | --- | --- |
| 通用首页与对话 | 通用输入框；四个快捷入口；最近对话、资料和任务；最小会话列表、新建与重命名 | 新安装默认进入通用首页；“新对话”确实隔离上下文；重启后历史可见且能正确续聊 |
| 写作与翻译 | 翻译、润色、总结、回复草稿四种内置操作；目标语言、语气等少量必要选项；结果复制、重试、保存笔记 | 用户不用编写提示词或安装 Skills；翻译目标语言不被界面语言覆盖；失败保留输入 |
| 文件阅读 | TXT、Markdown、文字型 PDF、DOCX 的文字提取；单文件总结与问答；文件名和片段引用 | 解析结果可预览；引用指向实际输入；资料里没有答案时明确说明；扫描件、损坏和加密文件提示原因 |
| 资料库 | 复用现有笔记；保存回答、摘录和来源链接；基础搜索、标签、收藏；Markdown 导出 | 无模型时可新增、编辑、查找、导出；保存成功以持久化结果为准；删除复用可靠撤销 |
| 资料整理助手 | 新增一条固定任务流，把用户选择的文件或笔记整理成资料报告；输出 Markdown 和 DOCX | 从任务中心启动、查看进度、暂停、取消、恢复；只有产物写入和校验成功才标记完成 |
| 模型接入引导 | 整理现有服务商配置流程，提供连接测试和可理解的错误提示；保留已有配置 | 不覆盖老用户配置；没有连接时明确说明 AI 功能状态；本地笔记、文件文字预览仍可使用 |

文件阅读处理正文与可提取的表格文字，不承担原文排版还原。首轮引用定位到原文片段；只有解析器可靠提供页码时才显示页码。DOCX 导出采用现有简洁文档样式。

文档问答采用本次明确选择的材料，首轮不要求用户配置嵌入模型或建立全库检索。建议初始限制为单文件 10 MB、一次最多 5 份、合计提取文本不超过 30,000 字符；这些是工程上限，不能保证任意自定义模型都具有足够上下文。解析器另外限制 DOCX 解压体积、条目数及耗时，模型拒绝或上下文不足时提供可理解的失败信息。超限在执行前告知，不静默丢弃正文。

**资料整理助手的具体定义**

示例需求：“根据这三份产品资料，整理主要特点、共同点、差异和待确认问题。”

输入为 1–5 份用户选择的已解析资料，以及本次整理目标。执行前展示材料清单和交付物；本次授权只覆盖这些材料。本轮不自行联网补充资料。

固定步骤：冻结资料快照 → 按材料提取要点 → 汇总与比较 → 检查结构和引用 → 写入报告 → 重读验证产物。

报告包含概览、分材料要点、综合整理、资料缺口与来源。事实、模型归纳和建议在表达上区分。未知引用 ID、引用片段不属于输入、空产物、写入失败等情况不能显示完成。

机器验证负责文件完整性、结构和引用可追溯性；模型总结是否忠实、判断是否合理，另用固定样例和人工抽查验收。文件哈希通过不等于内容事实已验证。

修改整理目标后作为新运行执行；已完成报告保持原快照。需要编辑时另存笔记或导出文件，避免编辑使原有验证记录失真。暂停、取消、异常恢复沿用已有任务状态机，应用重启后由用户决定继续。

**入口与已有用户的处理**

建议主导航为：首页、工具、资料库、任务。应用管理、能力中心与设置放在次级入口；求职仍可通过应用入口访问。

- 新安装：展示通用内容，求职应用可按需开启；求职演示数据由用户选择载入。
- 已有安装：保留求职数据、启用状态、模型配置、授权、对话和已有任务，增加通用入口。
- 资料库沿用现有 assets 数据所有权，笔记复用既有集合，不通过改显示名复制或搬空数据。
- 任务入口提升为平台公共入口；已有两条求职任务按原应用启用与权限规则显示和执行。
- 旧对话必须有可追溯的兼容归属；新会话采用独立历史作用域。项目管理不会因会话改造开放给 AI 修改。
- 不因升级自动扩大 AI 数据权限。手动保存笔记只进行本地保存，“AI 整理”由用户主动触发；“保存”与“加入知识库”分开。

**实现依据与架构工作**

| 现有基础 | 本轮实现方式 |
| --- | --- |
| 平台壳、应用 manifest、RuntimeApi / SeekerShellApi | 首页和通用任务入口属于平台；日常工具通过独立应用注册；资料保存走壳契约，应用间不互相 import |
| 多协议 AI 网关、无工具生成入口 | 复用供应商适配；写作和文档处理使用受限调用，隔离无关历史、项目指令、知识库和工具 |
| 消息持久化与项目历史桶 | 补齐会话契约、会话范围内历史恢复与旧记录兼容，防止界面显示历史而模型实际没有历史 |
| PDF 文字提取、DOCX 导出 | 复用现有实现，新增受控 DOCX 文字解析；通用解析结果带文件身份、片段标识和错误状态 |
| assets 笔记与 Markdown 编辑器 | 增加显式保存回答/摘录的契约、收藏和来源字段，清理与新定位冲突的退役引导和自动整理行为 |
| Task Agent 状态机和产物验证 | 增加编译期固定的资料整理工作流；平台任务展示与求职专用输入组件解耦 |
| Web 演示代理 | 更新通用定位与求职限定提示；继续仅提供其已实现的聊天能力，本轮不把它扩成桌面 Agent 服务 |

文件保存到应用管理的本地范围，用户原文件保持原样。模型不提交磁盘路径。任务读取已选择的资料快照，导入的授权字段不能替代本机授权。

新增会话或文档记录时，统一核对 Runtime 类型、桌面表映射、Web IndexedDB、便携备份和 AI 静态白名单。文件资料本轮通过选中材料的窄接口进入模型，不自动加入全库 AI 查询。新增的本地文件副本必须明确备份覆盖范围，便携导入后需要补齐的附件必须展示为待补齐。

原始文件解析、本地存储与发送给模型是不同动作。文件解析与普通保存默认本地完成；使用云端 AI 时，执行界面说明本次将发送哪些材料。现有隔离 profile 不参与这些流程。

**开发顺序**

| 批次 | 工作 | 可检查的结果 |
| --- | --- | --- |
| 1 · 入口与会话 | 通用首页、导航、首次引导、会话隔离与恢复、旧用户兼容、通用提示 | 新旧用户都能正常进入；新对话和继续历史对话均可用；求职仍可访问 |
| 2 · 写作与保存 | 四种日常操作、结果状态、保存笔记的契约、资料库基础整理、显式 AI 整理 | 一段文字经过处理后能成为持久化笔记；无模型时笔记主链可用 |
| 3 · 文件阅读 | 文件导入与解析、资料保存、受限问答、原文片段定位、解析失败与超限处理 | 拖入真实文件，能阅读、提问、检查引用；无关资料不会进入调用 |
| 4 · 资料整理任务 | 通用任务页面、新固定工作流、输入快照、报告生成、恢复与产物验证 | 多份文件产出可预览的 Markdown / DOCX，失败和中断状态可信 |
| 5 · 内测验收 | 模型连接引导、双语与两端降级核查、数据兼容、全量检查、文档 | 提供可复现验收脚本、验证记录、样例报告和已知限制 |

每批形成可运行的完整增量，再推进下一批。开发批准后按此顺序连续推进；若需要改变上述用户可见范围或引入新的服务费用，先说明具体变化。

**本轮取舍**

本轮交付定义为桌面功能内测版。桌面 AI 仍需要一次模型配置，可由内测组织者协助完成；真正免 Key 的托管模型服务是面向普通用户公开试用的前置工作，建议单独安排下一轮。

现有 Web 体验码仅能解决浏览器聊天试用。托管桌面执行还需要独立的鉴权、持久化额度、限流、成本控制和运行维护，不能直接以当前演示代理替代。

以下项目暂不纳入本轮：

- 托管模型账户、充值订阅、多端同步与移动端。
- 联网研究、自动浏览网页、邮件发送、跨应用自动操作。
- 任意 Shell、通用文件夹整理、用户自定义工作流或多 Agent 编排。
- 图片生成、图片 OCR、录音转写、扫描 PDF、PPT/Excel 专项处理。
- 独立待办提醒系统、PDF 合并拆分、图片压缩等额外工具。
- 操作系统后台调度，以及应用退出后继续执行。

这些是阶段范围安排，不代表后续产品方向取消。首轮非 AI 使用价值主要由笔记、摘录收藏、搜索、文件文字预览和导出提供。

**验收与试用目标**

工程验收：

- 五条用户路径都在真实 UI 走通；桌面文件和任务能力以真实桌面运行验收。
- 新会话、重启续聊、取消、错误重试和保存失败都有明确行为；失败不会生成“已完成”状态。
- 备份导入导出保全新增记录；旧求职数据与任务可继续使用；未授权数据不可读。
- 为会话隔离、文件范围、恶意文档指令、伪造引用、任务中断和写入失败保留正向控制与拒绝断言。
- 以文字 PDF、DOCX、TXT/MD、多材料报告、无答案问题及异常文件建立固定样例；结构验证和模型内容质量分别记录。
- 真模型验收覆盖当前可用服务；协议适配用确定性测试覆盖四种协议。无凭据或环境不支持的实测如实列为未覆盖。
- 浏览器经本地 HTTP 验证首页、笔记、兼容与降级；Web 对本轮未实现的文件问答、生成与任务执行明确禁用并解释。
- 更新 ARCHITECTURE、QUICKSTART 与对应用户文档；实际行为落地时再更新 CLAUDE 的产品事实和阶段描述。

跨层交付运行仓库全量检查：

```bash
npm test
npm run typecheck
npm run test:e2e
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml
cargo build --manifest-path src-tauri/Cargo.toml
```

最后一次桌面构建应实际重新编译、嵌入前端资源。只有用户明确要求安装包时才执行 build:all；推送、PR、tag 和发布单独遵循用户授权。

建议功能完成后邀请 5 位目标用户，模型连接完成后，至少 4 位无需开发者指导即可完成写作保存与单文件阅读；观察一周内是否至少 3 位在两个不同日期主动再次使用。此为小样本探索目标，不作为已经验证的需求结论，也不阻塞代码交付。

使用观察以自愿反馈和现场任务记录为主，本轮不新增默认上传行为或内容的遥测。
