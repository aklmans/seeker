# Widget 视觉与交互

show_widget 用于有助于理解的交互图表、计算器、对比或清单。模型生成内容结构和局部交互，
Seeker 提供统一的文字层级、原生控件、焦点、间距和明暗配色。应用壳的设计语言保持不变。

## 外观与交互

- 新 Widget 默认跟随应用主题；若已在设置里明确保存个人默认样式，则使用该独立风格。
- 在“设置 → 作品样式”选择“应用默认”并保存，可以恢复新 Widget 的主题跟随。
- 在单个 Widget 的作品页选择“跟随应用主题”或某个独立风格，保存后跨重启保留。
- “保存到我的样式”只保存独立风格；跟随主题时显示说明并禁用收藏入口。选择独立风格后即可自定义、收藏及设为个人默认。
- 切换应用主题不会清空正在调整的参数。重新加载、重新打开原稿或切换作品风格会初始化交互。
- 脚本出错时，显示恢复入口和可展开的错误详情。WebKit 的隔离机制可能只提供 `Script error.`。
  重新加载可处理临时故障，不能修复源码中的确定性错误；桌面版可以打开作品，用“AI 修改 Widget”
  生成修复预览，检查后应用并保存。手工修改仍在高级 HTML 入口，版本记录可以恢复。

## 生成规范

模型收到的完整规范在 [widget-design.md](../src-tauri/src/widget-design.md)。模型输出无头 body 片段，
不再负责整个页面、导航、基础字体、主题和控件皮肤。已有 `sw-layout`、`sw-controls`、`sw-field`、
`sw-stats`、`sw-note` 等通用布局，窄画布自动堆叠。

SVG 优先使用 `viewBox`、可读标签和 `--chart-1` 至 `--chart-4` 颜色；Canvas 必须读取解析后的 CSS
颜色，并监听 `seeker:themechange` / `seeker:resize` 重绘。控件有标签、即时值、合理默认值和重置入口。
图表应该有初始结果和简短解释，不能只留下空白占位。组件只有内联 HTML/CSS/原生 JS，没有外部库、
网络、存储或父页面访问权限。

这些规则和底座不能保证所有模型始终遵守，也不能证明模型计算正确。旧 HTML 中写死的样式或错误脚本
不会被批量重写；切换主题无法修复脚本。需要对该作品应用修订版，或按新规范重新生成。

## 导出

PNG/PDF 捕获当前结果，冻结主题、SVG 颜色与标准滑块位置。离线 HTML 保持交互，但从源码初始状态开始，
使用导出时的配色。复杂自定义 CSS、动画和特殊控件仍可能有重建差异，分享前检查真实预览。
折叠的说明正文不会出现在静态快照里，展开后才导出。

## 本机验收（2026-09-09）

1. 原始供需 Widget：已从本机对应作品只读取得源码并复现空白图表。`Y=v=...v...` 误把坐标函数写成
   赋值，运行时读取未定义的变量；原始作品记录未改写。
2. 修订供需样例：使用同一渲染器和无头控件，在 Chromium、WebKit 与原生 macOS 窗口验证初始曲线、
   参数变化、边界值和重置。样例位于 `test/e2e/fixtures/supply-demand.html`，只是验收材料，不是新增产品入口。
3. 主题与样式：验证热切换保留参数、主题模式保存重开、显式个人风格不受应用主题影响；窄画布无横向溢出，
   滑块可用键盘调整并显示焦点。这里没有宣称完整无障碍合规。
4. 导出：真实桌面发现 SVG 丢色及 range 被当作文字的错误；先增加失败的 PNG 像素断言（曲线颜色像素为 0），
   再固定 SVG 样式和标准滑块。修复后同一测试在两个浏览器通过。快照保持当前主题，不复用旧主题变量。

自动化命令：`npm test`、`npm run typecheck`、`npm run test:e2e -- --workers=4`；Rust fmt、clippy、tests、
`cargo build`。桌面使用独立 `dev.zhapar.seeker.round2` 数据目录与本地确定性模型响应，确认实际出网请求
包含新生成规范。没有使用云端模型验证生成质量，没有进行 Windows 真机验证，也未打包发布。

视觉底座初次验收结果：Node 160 项通过；Chromium 63 项、WebKit 63 项（共 126 项）通过；typecheck、Rust fmt、
clippy 通过；Rust 244 项单测及 1 项解析进程集成测试通过，4 项 ignored。最终默认配置的 `cargo build`
实际重新编译 `app v0.4.0` 并嵌入前端。原生窗口完成参数 50 → 83、切主题保留 83、作品重启重开、
修复后 PNG 预览及文件写入校验。验收环境恢复此前的深色与“纸上阅读”默认值。

### P2 复验修复（2026-09-09）

- 卡片直接移除、祖先容器移除都会在 DOM 移除监听中关闭真实 MessagePort，释放注册引用和消息处理器，
  取消通道中未完成的导出。跟随主题与独立风格都覆盖；其他卡片仍可切主题和导出，关闭全部后再新建仍正常。
- 跟随主题时禁用收藏入口并显示说明，保存函数及默认偏好入口也拒绝该模式。旧版误存的 auto 收藏不可复用或
  设为个人默认；原始记录和偏好不自动重写。独立风格仍可自定义、收藏并作为新 Widget 的默认值。
- 先补失败回归：修复前 Chromium 的 4 个用例分别复现两种样式的端口未关闭、auto 收藏入口可用、旧 auto 收藏
  可设默认。修复后 `widget-lifecycle.spec.mjs` 与 `creation-style.spec.mjs` 共 20 个跨浏览器用例通过，
  包含重载取消旧导出、新通道继续导出、收藏/设置默认/重启/生成作品完整流程和旧数据保护。
- 全量验证：`npm test` 160 项；`npm run typecheck`；`npm run test:e2e -- --workers=4` Chromium 68 项、
  WebKit 68 项，共 136 项通过。Rust fmt、clippy 通过；244 项单测和 1 项集成测试通过、4 项 ignored。
  最终默认配置的 `cargo build --manifest-path src-tauri/Cargo.toml` 实际重新编译 `app v0.4.0` 并嵌入前端。
- 原生 macOS 使用独立验收数据验证 auto 禁用说明 → 柔和启用 → 收藏表单 → 取消与放弃草稿 → 恢复 auto 禁用，
  并截取真实窗口。未改写已有作品或默认值；未进行 Windows 真机、屏幕阅读器或云端模型验收，未打包发布。
